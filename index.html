One browser API for emulated computers

Webulator runs WebAssembly emulators in a worker and puts them behind one contract: snapshots, exact pointer input, a virtual clock and copy-on-write disks. A core counts as supported only when it passes the same twelve conformance tests as every other core.

    The API

    A profile names the core, the machine model and the disk images. Everything after Machine.create is the same for every core.

    import { Machine, loadProfile } from "webulator";

const m = await Machine.create({
  profile: await loadProfile("sheepshaver-g3bw-macos904.json"),
  snapshot: { url: "finder.webusnap" },   // skip the boot
  display: canvas,
});

m.input.pointer.moveTo(20, 8);    // guest pixels, lands exactly
m.input.pointer.button(0, true);
await m.input.type("Hello");

await m.pause();                   // the guest clock stops too
const state = await m.saveState();   // CPU, RAM, devices, disk writes
const writes = await m.disks.get("hd0").exportOverlay();
    Equal capabilities, nothing optional
    A capability enters the contract only once every core implements it and passes its tests. Hardware differences such as screen sizes and mouse buttons are reported as properties.
    Snapshots restore to the same pixel
    A saved state restores into a fresh worker, and its first frame matches the saved frame exactly.
    A virtual clock
    The guest sees no time pass while it is paused or stored, so a restored machine behaves like one that never stopped.
    Disk fetches never stall the guest
    Disk images load lazily over the network. While a chunk is on its way the guest keeps running, so the cursor keeps moving, as on a real machine with a busy disk.
